# 上海买房板块地图 · 制作与更新指南

一个完全自包含的交互式 HTML 地图：全市 217 个街镇级板块按行政区着色，
叠加内环/中环/外环/郊环（实线）与 18 条地铁线路（官方色虚线），
点击板块显示参考挂牌价。生成的 HTML 单文件即可分享，双击浏览器打开，
无需服务器；联网时自动加载街道底图（OpenStreetMap HOT 风格，OSM 法国托管），离线也能正常看板块和线路。

## 目录结构

```
shanghai-map-kit/
├── README.md            ← 本文件
├── boards.py            ← ★ 房价数据（更新房价只改这里）
├── build_map.py         ← ★ 一键生成地图
├── update_prices.py     ← 用贝壳数据自动更新房价
├── locate_boards.py     ← 用高德定位板块坐标（新增板块时用）
├── boards_edit.py       ← 上面两个脚本共用的 boards.py 改写函数
├── template.html        ← 页面模板（样式、交互逻辑）
├── fetch_geodata.py     ← 重新抓取地理数据（一般用不到）
├── data/                ← 地理数据（已带好现成的）
│   ├── towns.json       ← 217 个街镇边界（OpenStreetMap，已抽稀）
│   ├── districts.json   ← 16 个区界（阿里云 DataV）
│   ├── ring_roads.json  ← 内环/中环/外环S20/郊环G1503
│   └── metro_lines.json ← 地铁 1–18 号线走向及官方配色
└── vendor/              ← Leaflet 1.9.4（构建时内联进 HTML）
```

## 日常更新房价（最常用）

1. 用贝壳数据自动更新（推荐）。需要本机装好贝壳 CLI `beike` 并已登录
   （`beike doctor` 全部通过）：

   ```bash
   python3 update_prices.py            # 抓取并打印新旧对比，不改文件
   python3 update_prices.py --apply    # 看过对比后写回 boards.py
   ```

   - 每个板块取贝壳"上榜小区"挂牌均价的 25%–75% 分位作为区间，
     是**挂牌价不是成交价**；小区榜偏向成交活跃的老小区，
     次新房、豪宅多的板块会偏低，写回前先看一眼对比表。
   - 上榜小区不足 10 个，或者贝壳的商圈和板块对不上（前滩、世博滨江等），
     不会自动更新：保留旧值，并在 `boards.py` 行尾注明。
     这些板块要手动核对：v1.5.0 用房天下对应商圈的小区均价（同样取 25%–75% 分位）
     补齐了，来源写在行尾注释里。
   - 贝壳 Key 每天大约只能调用 150 次，全量要 136 次。结果按月缓存在
     `.cache/beike/<年-月>/`，中途触顶就第二天再跑，会接着抓。

   也可以直接手改 `boards.py`，每行一个板块：

   ```python
   # (板块名, 区, 纬度, 经度, 价格低位, 价格高位, 是否重点板块, 环线位置)
   ("前滩", "浦东", 31.1487, 121.4703, 12, 16, 1, "中环沿线"),
   ```

   价格单位是 **万元/㎡**。文件底部 `DISTRICT_PRICE` 是各区整体均价（元/㎡），
   用于没有细分板块数据的街镇，需要手动更新。

2. 更新文件顶部的**版本信息**三项：`VERSION`（版本号）、
   `DATA_DATE`（数据年月，`update_prices.py --apply` 会自动改）、
   `UPDATE_NOTE`（一句话说明）。版本号和数据月份会显示在地图标题、
   页脚和板块弹窗里；构建时还会自动把本次更新追加到 `CHANGELOG.md`。

3. 运行构建（只需要 Python 3，不装任何库）：

   ```bash
   python3 build_map.py
   ```

4. 生成 `上海买房板块地图.html`（约 1 MB），
   双击打开检查，直接发文件给别人即可。

构建脚本会自动把每个板块价格点匹配到所在街镇
（点击街镇时弹窗里列出的细分价格就来自这一步），
控制台会提示是否有坐标没落进任何街镇。

## 新增板块 / 校正坐标

坐标必须是 GPS/WGS-84（底图用的就是 WGS-84）。高德拾取、高德 API、
贝壳返回的都是 GCJ-02，直接填会整体偏移约 500 米。用脚本自动定位：

1. 在 `boards.py` 里照格式加一行，坐标先填 `0, 0`；
2. 运行（需要环境变量 `AMAP_WEBSERVICE_KEY`，即高德「Web服务」类型的 Key）：

   ```bash
   python3 locate_boards.py 新板块名 --apply
   ```

脚本优先用高德的"热点地名"（商圈/片区中心）定位，再转换成 WGS-84，
并检查点是否落在所属区的街镇边界内。热点地名不准的板块，
在脚本顶部的 `LANDMARK` 里指定一个地标。不带板块名运行会检查全部
板块与现有坐标的偏差（只打印，不加 `--apply` 不改文件）。

## 更新地理数据（偶尔）

地铁开新线、行政区划调整时才需要。需要联网：

```bash
python3 fetch_geodata.py           # 全部重抓（约 2–4 分钟）
python3 fetch_geodata.py metro     # 只重抓地铁
```

数据来源与处理：

| 数据 | 来源 | 处理 |
|---|---|---|
| 街镇边界 | OSM Overpass：`admin_level=8` 的行政边界关系 | way 拼接成闭合环 → Douglas-Peucker 抽稀（约60米容差）→ 质心落区判定所属区 |
| 区界 | 阿里云 DataV `areas_v3/bound/310000_full.json` | 直接使用 |
| 环线 | OSM：`内环高架路`（way 名）、`中环路`（route 关系）、`S20`、`G1503`（route=road 关系） | 双向去重 → 拼接 → 抽稀 |
| 地铁 | OSM：`route=subway` 关系，每条线取一个方向 | 拼接 → 抽稀，颜色取 OSM `colour` 标签（即官方线路色） |

Overpass 公共服务器偶尔繁忙，脚本会自动换镜像重试；都失败就过几分钟再跑。

## 改样式

都在 `template.html` 里：

- **行政区配色**：`DCOLOR` 对象（16 个区 → 16 种颜色，相邻区刻意错开色相）。
- **线型**：环线在 `ringStyle`（实线+白描边），地铁在 metro 段
  （`dashArray:'7 6'` 即虚线样式）。
- **标签显示门槛**：`refreshLabels()` 里 `px2 > 2600`（显示板块名）
  和 `px2 > 6000`（显示价格）——数值越小标签越密。
- **价格弹窗、图例、开关**：对应的 HTML/CSS 都有中文注释可循。

改完模板后重新 `python3 build_map.py` 即可。
