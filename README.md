# 上海买房板块地图 · 制作与更新指南

一个完全自包含的交互式 HTML 地图：全市 217 个街镇级板块按行政区着色，
叠加内环/中环/外环/郊环（实线）与 18 条地铁线路（官方色虚线），
点击板块显示参考挂牌价。生成的 HTML 单文件即可分享，双击浏览器打开，
无需服务器；联网时自动加载街道底图（OpenStreetMap HOT 风格，OSM 法国托管），离线也能正常看板块和线路。

## 目录结构

```
shanghai-map-kit/
├── README.md            ← 本文件
├── boards.py            ← ★ 房价数据（更新房价只改这里）
├── build_map.py         ← ★ 一键生成地图
├── update_prices.py     ← 用贝壳数据自动更新房价
├── export_schools.py    ← 从主仓库导出全市小学/初中对口，按街镇聚合成 JSON
├── locate_boards.py     ← 用高德定位板块坐标（新增板块时用）
├── boards_edit.py       ← 上面两个脚本共用的 boards.py 改写函数
├── template.html        ← 页面模板（样式、交互逻辑）
├── fetch_geodata.py     ← 重新抓取地理数据（一般用不到）
├── fetch_stations.py    ← 重新抓取地铁站（已开通 + 在建/规划）
├── check_plan_layer.py  ← 检查控规图层的瓦片服务和图例配色是否还对得上
├── data/                ← 地理与学区数据（已带好现成的）
│   ├── towns.json       ← 217 个街镇边界（OpenStreetMap，已抽稀）
│   ├── districts.json   ← 16 个区界（阿里云 DataV）
│   ├── ring_roads.json  ← 内环/中环/外环S20/郊环G1503
│   ├── metro_lines.json ← 地铁 1–18 号线走向及官方配色
│   ├── metro_planned.json        ← 在建/规划地铁
│   ├── stations.json             ← 地铁站（fetch_stations.py 生成）
│   ├── stations_manual.json      ← 在建站人工补点（写明来源，优先于自动来源）
│   ├── school_districts.json     ← 学区对口（export_schools.py 生成，← 地图读这个）
│   └── newhomes.json             ← 新房楼盘（房天下，含经纬度与单价；可选，见“更新新房数据”）
└── vendor/              ← Leaflet 1.9.4（构建时内联进 HTML）
```

## 日常更新房价（最常用）

1. 用贝壳数据自动更新（推荐）。需要本机装好贝壳 CLI `beike` 并已登录
   （`beike doctor` 全部通过）：

   ```bash
   python3 update_prices.py            # 抓取并打印新旧对比，不改文件
   python3 update_prices.py --apply    # 看过对比后写回 boards.py
   ```

   - 每个板块取贝壳"上榜小区"挂牌均价的 25%–75% 分位作为区间，
     是**挂牌价不是成交价**；小区榜偏向成交活跃的老小区，
     次新房、豪宅多的板块会偏低，写回前先看一眼对比表。
   - 上榜小区不足 10 个，或者贝壳的商圈和板块对不上（前滩、世博滨江等），
     不会自动更新：保留旧值，并在 `boards.py` 行尾注明。
     这些板块要手动核对：v1.5.0 用房天下对应商圈的小区均价（同样取 25%–75% 分位）
     补齐了，来源写在行尾注释里。
   - 行尾注释写了"房天下"的板块，`--apply` 不会再用贝壳值覆盖，
     对比表后会单独列出贝壳值供参考；确实要覆盖时加 `--override-fang`。
   - 贝壳 Key 每天大约只能调用 150 次，全量要 136 次。结果按月缓存在
     `.cache/beike/<年-月>/`，中途触顶就第二天再跑，会接着抓。

   也可以直接手改 `boards.py`，每行一个板块：

   ```python
   # (板块名, 区, 纬度, 经度, 价格低位, 价格高位, 是否重点板块, 环线位置)
   ("前滩", "浦东", 31.1487, 121.4703, 12, 16, 1, "中环沿线"),
   ```

   价格单位是 **万元/㎡**。文件底部 `DISTRICT_PRICE` 是各区整体均价（元/㎡），
   用于没有细分板块数据的街镇，需要手动更新。

2. 更新文件顶部的**版本信息**三项：`VERSION`（版本号）、
   `DATA_DATE`（数据年月，`update_prices.py --apply` 会自动改）、
   `UPDATE_NOTE`（一句话说明）。版本号和数据月份会显示在地图标题、
   页脚和板块弹窗里；构建时还会自动把本次更新追加到 `CHANGELOG.md`。

3. 运行构建（只需要 Python 3，不装任何库）：

   ```bash
   python3 build_map.py
   ```

4. 生成 `上海买房板块地图.html`（约 1 MB），
   双击打开检查，直接发文件给别人即可。

构建脚本会自动把每个板块价格点匹配到所在街镇
（点击街镇时弹窗里列出的细分价格就来自这一步），
控制台会提示是否有坐标没落进任何街镇。

## 学区对口（全市，公办小学 + 初中）

点击板块或街镇，弹窗底部有「对口小学」「对口初中」两栏，列出该街镇里
已收录小区对口的学校，点学校名展开对口的小区。

- 数据来自主仓库 `../shanghai-ai-housing` 的 `estate_schools` 表：主仓库按
  各区教育局招生地段公示，把「小区 → 对口学校」算好存库（`scripts/estates.py schools`）。
  本仓库只读取，不改动主库。
- **是按小区汇总的，不是完整地段**：只有主仓库收录并匹配上对口学校的小区才会出现。
  各区收录差异很大（导出时会打印每个区的「收录小区 / 小区总数」，也写在
  `meta.coverage` 里），比如浦东、闵行、徐汇比较全，虹口、静安、黄浦、嘉定很少；
  有 34 个街镇一个小区都没有，弹窗里不显示这一栏。没出现的小区不代表没有对口学校。
- 小区落到街镇：先用小区自带的街镇名（要与 `towns.json` 同区同名），对不上再用
  小区坐标（高德 GCJ-02 转 WGS-84）判断落在哪个街镇；两样都没有的小区不上图。
- 板块弹窗里的对口学校是按「板块点落在哪个街镇」取的，属于街镇口径，
  不等于该板块专属对口。
- 小区上的备注（鼠标悬停可见，带橙色下划线）：`部分`（只有部分楼栋对口）、
  `门牌段`（按门牌号段命中）、`补充`（补充公示）、`经XX小学`（初中由对口小学
  推出，长宁、徐汇等区多校划片时一个小区会列出好几所初中）、
  `一贯制直升（推断）`（不是正式对口）。

更新（主仓库重算过对口、或换了年份）：

```bash
python3 export_schools.py            # 默认读 ../shanghai-ai-housing/data/housing.db，可用 --db 指定
python3 build_map.py
```

## 更新新房数据

地图右上角图层面板有一个「新房楼盘」开关，**默认关闭**：打开后按单价分档
（<3 / 3–5 / 5–7 / 7–10 / ≥10 万/㎡，与价位筛选的区间一致）用小圆点画出
全市新房楼盘，实心=在售、空心=待售，缺单价的用灰点；点击看详情，
图层打开时板块/街镇弹窗末尾会多一句本区域新房统计（个数、在售数、在售均价）。

数据不在本仓库生成，而在 `../shanghai-ai-housing`：

```bash
cd ../shanghai-ai-housing
python3 scripts/newhome.py locate --limit 0   # 用高德定位楼盘坐标（有调用额度，可以分天续跑）
python3 scripts/newhome.py export-map         # 写出本仓库的 data/newhomes.json

cd ../shanghai-map-kit
python3 build_map.py                          # 重新构建，控制台会打印新房统计
```

- 只显示有住宅证据的楼盘——住宅类标签、贝壳物业类型为住宅/别墅、或有户型信息；商办和查不清的不显示；个别楼盘在主仓库 `config/newhome_map_override.yaml` 人工指定。
- `locate` 调用高德地理编码，“先定位、再导出”，额度用完就第二天再跑，
  已定位的楼盘会保留（`meta.located` / `meta.total` 会显示在图例里）。
- 坐标导出时已经转成 WGS-84，和底图一致，不需要再处理。
- `build_map.py` 会先把每个楼盘落到所在的板块单元和街镇（`cell` / `town`
  下标），落不进的为 `null`（这些点仍然上图，但不计入板块/街镇统计）。
- **这个文件是可选的**：没有 `data/newhomes.json` 也能构建，只是日志会打一条
  警告，产物里没有新房数据，图层面板也不显示这个开关。

## 新增板块 / 校正坐标

坐标必须是 GPS/WGS-84（底图用的就是 WGS-84）。高德拾取、高德 API、
贝壳返回的都是 GCJ-02，直接填会整体偏移约 500 米。用脚本自动定位：

1. 在 `boards.py` 里照格式加一行，坐标先填 `0, 0`；
2. 运行（需要环境变量 `AMAP_WEBSERVICE_KEY`，即高德「Web服务」类型的 Key）：

   ```bash
   python3 locate_boards.py 新板块名 --apply
   ```

脚本优先用高德的"热点地名"（商圈/片区中心）定位，再转换成 WGS-84，
并检查点是否落在所属区的街镇边界内。热点地名不准的板块，
在脚本顶部的 `LANDMARK` 里指定一个地标。不带板块名运行会检查全部
板块与现有坐标的偏差（只打印，不加 `--apply` 不改文件）。

## 控规图层（不用更新，偶尔检查）

图层面板的「规划用地（控规）」开关（默认关闭）叠加的是上海市规划和自然资源局的控规地块瓦片，
浏览器打开地图时**实时**从对方服务器加载，没有存进仓库也没打包进 HTML：
对方数据更新后地图自动跟着变（浏览器缓存最多一天），不用重新构建。

会让它出问题的只有两种变化：服务地址变了 / 下线（图层空白，图例会提示加载失败），
或官方改了用地配色（图例对不上）。偶尔手动检查一下：

```bash
python3 check_plan_layer.py     # 0 = 正常；1 = 有项目不通过，按提示改 template.html 后重新构建
```

瓦片地址和图例都在 `template.html`（`planLayer` 和 `PLAN_LEGEND`，图例每项第三个值是官方用地代码）。

## 更新地理数据（偶尔）

地铁开新线、行政区划调整时才需要。需要联网：

```bash
python3 fetch_geodata.py           # 全部重抓（约 2–4 分钟）
python3 fetch_geodata.py metro     # 只重抓地铁
```

数据来源与处理：

| 数据 | 来源 | 处理 |
|---|---|---|
| 街镇边界 | OSM Overpass：`admin_level=8` 的行政边界关系 | way 拼接成闭合环 → Douglas-Peucker 抽稀（约60米容差）→ 质心落区判定所属区 |
| 区界 | 阿里云 DataV `areas_v3/bound/310000_full.json` | 直接使用 |
| 环线 | OSM：`内环高架路`（way 名）、`中环路`（route 关系）、`S20`、`G1503`（route=road 关系） | 双向去重 → 拼接 → 抽稀 |
| 地铁 | OSM：`route=subway` 关系，同一线路号的所有关系（两个方向 + 支线） | 按 way 去重 → 拼接 → 去掉重合的双线 → 抽稀，颜色取 OSM `colour` 标签（即官方线路色） |
| 地铁站 | 见下 | `fetch_stations.py` |

### 地铁站

```bash
python3 fetch_stations.py            # 重新抓取，生成 data/stations.json
python3 fetch_stations.py --cached   # 只用 .cache/stations/ 里上次下载的原始数据重新合并
```

- **已开通站**：OSM 地铁/市域线路关系里的停车点，同名取中心，线路归属取自关系。
  OSM 还没收录的新开通站用 Wikidata 坐标补。
- **在建/规划站名单**：中文维基百科各线路条目的车站表（表内引用上海市规划资源局选线专项规划、
  环评公示和招标公告）。站名可能是工程名。
- **在建站坐标**：`data/stations_manual.json` → OSM 在建车站标注 → Wikidata → 维基百科车站条目坐标。
  都没有的站不上图，脚本结束时列出；查到位置后补进 `stations_manual.json`
  （`{"站名": {"lng", "lat", "src", "date"}}`，坐标用 WGS-84，高德坐标先转换）。

Overpass 公共服务器偶尔繁忙，脚本会自动换镜像重试；都失败就过几分钟再跑。

## 回归测试

改完 `template.html` / `build_map.py` / `export_schools.py` 后跑一遍：

```bash
python3 tests/regression.py        # 全量（含与 HEAD 基线对比）
python3 tests/regression.py -v     # 列出每一条通过的用例
```

覆盖五块：构建链路（三个产物一致、占位符已替换、体积合理）、
与 `HEAD` 构建结果的逐项数据不变量（板块/街镇/环线/地铁/区价）、
学区导出（结构与计数自洽、去重、可重现；没有主库时跳过）、缺 `school_districts.json` /
`newhomes.json` 时的降级，以及用无头 Chrome 真实打开地图跑交互
（双视图切换、各图层开关、标签阈值、价位筛选、新房图层与价位筛选联动、
各类弹窗、学区折叠展开，并收集 JS 报错）。

两个注意点：

- 需要本机有 Chrome（或 `CHROME=/path/to/chrome`）；没有就跳过浏览器那部分。
- 「两次导出结果字节一致」会先读现有 `data/school_districts.json` 再跑一遍脚本对比，
  所以手改过这个 JSON、或主库刚重算过对口都会报错——它应当由 `export_schools.py` 生成，重跑一次即可。

## 改样式

都在 `template.html` 里：

- **行政区配色**：`DCOLOR` 对象（16 个区 → 16 种颜色，相邻区刻意错开色相）。
- **线型**：环线在 `ringStyle`（实线+白描边），地铁在 metro 段
  （`dashArray:'7 6'` 即虚线样式）。
- **标签显示门槛**：`refreshLabels()` 里 `px2 > 2600`（显示板块名）
  和 `px2 > 6000`（显示价格）——数值越小标签越密。
- **价格弹窗、图例、开关**：对应的 HTML/CSS 都有中文注释可循。
- **价位筛选**：左上角面板，`#pfChips` 里改快捷区间；筛选逻辑在 `applyFilter()`
  （板块价格区间与所填范围有重叠即算符合，没有细分价的街镇按区级均价算）。

改完模板后重新 `python3 build_map.py` 即可。

## 数据说明与免责

- 房价为**挂牌参考价**（2026年8月，综合房天下/安居客整理），
  郊区部分为估算；实际成交因楼龄、房型、楼层差异很大，仅供筛选板块参考。
- 学区对口数据来自各区教育局 2026 年公办小学、初中招生地段公示（经主仓库按小区匹配），
  只含已收录的小区、各区覆盖不均，且只到街镇口径；学校招生地段每年调整，
  实际入学以当年区教育局公示和学校招生简章为准。
- 街镇边界 © OpenStreetMap 贡献者（ODbL）；区界来自阿里云 DataV；
  底图瓦片 © OpenStreetMap，HOT 风格由 OSM France 托管（2026-10 起 CARTO 瓦片需 API Key 已停用；
  OSM 官方瓦片会拒绝本地 file:// 打开时的请求，所以没用）。分享时请保留地图右下角的版权注记。
